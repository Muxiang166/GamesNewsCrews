# 初次联网测试评分

测试时间参考：2026-05-11。  
测试目标：搜索 `Nintendo Switch 2` 近 `7d` 资讯，生成行业简报与社媒内容包。  
实际 token 消耗：44,517 tokens。

## 运行过程评分：42/100

主要问题：

- 时间约束失败：任务要求近 7 天，但搜索词实际是 `latest news 2025`、`release date news 2024`、`hands-on preview 2025`、`April 2025` 等，完全没有把当前日期 2026-05-11 或 lookback 窗口硬编码进检索。
- 搜索面太宽：8 次 DuckDuckGo 搜索都围绕单一关键词，没有固定游戏资讯源、国内社区源、梗图/热帖源，也没有站内搜索策略。
- 搜索结果不可控：DuckDuckGo 返回文本摘要而非结构化结果，导致发布时间、来源 URL、热度指标无法可靠读取。
- 证据链不足：大量来源写成“综合报道”“Nintendo官网、IGN、Eurogamer”等泛称，没有落到可点击原始 URL。
- 下游 agent 没有复核工具：分析师只能基于研究员文本继续推理，无法独立抓网页或二次检索。
- token 使用偏高：44,517 tokens 对一次单主题 demo 偏贵，且很多 token 花在 verbose 日志、重复上下文和无效历史材料上。

可取之处：

- CrewAI 顺序流能跑通。
- 最终能生成 Markdown 与社媒内容包。
- 分析阶段识别到了“2025 年 3 月销量 vs 2025 年 6 月发售”的时间线矛盾，说明后续的验证角色是必要且有效的方向。

## 最终新闻评分：34/100

评分拆分：

- 时效性：5/30  
  输出报告期为 `2024年11月 - 2025年4月`，而当前日期是 2026-05-11，完全不符合近 7 天，更不符合未来目标中的过去 48 小时。
- 真实性与证据：10/25  
  有可信度分级意识，但引用不够具体。部分结论缺少原文链接，部分疑似矛盾数据仍进入正文。
- 选题匹配度：6/20  
  结果是传统硬件发售复盘，不是用户期望的“48 小时内高热度游戏资讯/梗图/玩家传播事件”。
- 可读性：10/15  
  Markdown 结构清楚，社媒文案可读。
- 可发布性：3/10  
  因时间错误、URL 不完整、配图方案依赖文生图且可能涉及版权/事实风险，不建议直接发布。

结论：这次结果只能作为流程验证样本，不可作为正式内容样本。

## 对后续路线图的直接启发

- 时间范围必须由代码层过滤，不能只写在 prompt 里。
- 搜索阶段先做站点白名单和高热度入口，而不是让 LLM 自由想搜索词。
- 抓取后必须保存结构化原始证据，Markdown 只是最终展示层。
- 热度必须有独立评分：评论、转发、点赞、弹幕、收藏、社区回复数、媒体转载数、搜索结果密度。
- 梗图/截图/封面图必须作为素材实体进入 pipeline，读取不到就标记 `manual_fill_required`，不要让 LLM 编图。
- LLM 只处理经过代码预筛的少量候选，减少 token 成本。
